# AI 狼人杀 (LLM-Powered Werewolf Game)

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Python Version](https://img.shields.io/badge/python-3.8%2B-blue.svg)](https://www.python.org/)

这是一个基于大型语言模型（LLM）的AI自动进行狼人杀游戏的项目。每个游戏角色都由一个独立的AI Agent扮演，它们拥有自己的角色设定、记忆和决策逻辑，通过精密的提示词工程（Prompt Engineering）驱动，模拟真人的发言、投票和战术行为，共同演绎一局完整的狼人杀对局。

## ✨ 项目特色

* **高度自动化**: 从角色分配、夜晚行动到白天发言和投票，整个游戏流程由程序自动驱动，无需人工干预。
* **动态AI玩家**: 每个AI玩家都由一个大型语言模型驱动，能够根据场上局势、历史信息和自身角色进行动态思考和决策。
* **模块化提示词系统**: AI的行为和角色扮演深度由 `doc` 文件夹下的 `.yaml` 文件定义。你可以轻松修改提示词，调整AI的性格、策略甚至创造新角色。
* **灵活的配置**: 首次运行时，程序会通过交互式命令行引导用户配置API密钥和玩家设置，支持多种模型和服务商。
* **可扩展的角色系统**: `core/init.py` 中的角色分配逻辑允许你轻松调整对局中的角色配置，如狼人、神民和村民的数量。
* **详细的日志记录**: 每一局游戏都会生成详细的日志文件，记录所有公共信息、私人信息以及AI的内部思考过程（被`<think>`标签包裹），便于复盘和调试。

## 🚀 快速开始

### 1. 先决条件

* Python 3.8 或更高版本
* 可以访问一个或多个兼容OpenAI API格式的大型语言模型服务

### 2. 安装

首先，克隆本项目到你的本地计算机：

```bash
git clone https://github.com/your-username/your-repository-name.git
cd your-repository-name
```

然后，安装所需的依赖库：

```bash
pip install -r requirements.txt
```

### 3. 配置

第一次运行项目时，你需要进行一些必要的配置。

直接运行 `main.py`：

```bash
python main.py
```

程序会自动检测 `config` 文件夹下是否缺少配置文件，并引导你完成以下设置：

1. **API预设配置 (`api_template.json`)**:
    * 程序会提示你“未检测到可用api预设”。
    * 你需要为你的大模型服务创建一个或多个“预设”。每个预设包含：
        * **预设名**: 自定义，如 `my_gpt4`。
        * **预设url**: API的Base URL。
        * **预设密钥**: 你的API Key。
        * **预设模型**: 你要使用的模型名称，如 `gpt-4-turbo`。
    * 你可以添加多个预设，以备后续为不同玩家分配不同模型。

2. **玩家配置 (`api_players.json`)**:
    * 完成API预设后，程序会引导你为每个玩家分配一个API预设。
    * 你需要为游戏中的N个玩家（例如1到8号）逐一指定他们将使用哪个API预设。

3. **角色分配**:
    * 配置完玩家后，程序会让你决定本局游戏的角色构成。
    * 你可以根据提示增加或减少狼人、预言家、女巫等角色的数量，村民数量会自动计算。
    * 请确保好人阵营数量大于狼人阵营数量。

完成以上步骤后，你的配置信息将保存在 `config` 文件夹中，下次运行时将直接读取，无需重复配置。

### 4. 运行游戏

配置完成后，再次运行 `main.py`（如果上一步没有中断的话会直接开始）。

```bash
python main.py
```

1. 输入一个**游戏窗口名称**，这将作为日志文件的一部分。
2. 选择游戏模式，当前推荐选择 `3`（新·全自动模式）。

之后，游戏将自动开始。你将在控制台看到游戏的实时进展，包括阶段变化（天黑/天亮）、AI玩家的思考过程和公开发言。

## ⚙️ 核心工作流

1. **初始化 (`init.py`)**: 程序检查配置，引导用户创建 `api_template.json` 和 `api_players.json`，并确定本局的角色 `roles`。
2. **提示词生成 (`init.py: role_json_made`)**: 根据确定的角色，程序会从 `doc` 目录读取对应的 `.yaml` 文件，整合成一份包含全局规则、角色专属规则的 `instructions.json`。
3. **游戏实例化 (`game.py: Game`)**: 创建一个 `Game` 实例，它作为游戏引擎，管理所有玩家、游戏阶段和核心逻辑。
4. **玩家实例化 (`player.py: Player`)**: `Game` 对象根据 `api_players.json` 创建多个 `Player` 实例。每个 `Player` 实例被赋予一个角色，并根据其角色和全局配置获得初始的系统提示词（System Prompt）。
5. **游戏循环 (`main.py`)**: 游戏按照 `Game.routines` 中定义的顺序循环执行，如：`守卫行动` -> `狼人行动` -> `预言家行动` -> `女巫行动` -> `公布死讯` -> `公共讨论` -> `投票放逐`。
6. **AI交互 (`player.py: get_response`)**:
    * 当轮到某个玩家行动或发言时，`Game` 对象会向对应的 `Player` 对象发送一个指令（例如“请投票”或“请发言”）。
    * `Player` 对象将这个指令、完整的历史对话记录 (`Context`) 和系统提示词一起打包，发送给大模型API。
    * AI的回复（包括内部思考 `<think>...</think>` 和最终发言）被接收。
7. **上下文管理 (`context.py: Context`)**: AI的每一次发言都会被包装成一个 `Context` 对象，并记录在全局上下文中。`Context` 对象严格定义了这条信息的**来源**、**内容**和**可见范围**（`visible_ids`），确保狼人私聊只有狼人可见，预言家查验结果只有预言家可见。

## 🔧 提示词系统详解

提示词是驱动AI行为的灵魂。本项目的提示词系统设计得非常模块化。

* **`doc/{role}.yaml`**: 定义了某个角色的核心玩法、目标和策略。例如，`doc/werewolf.yaml` 告诉AI狼人需要伪装、与队友合作、刀杀神民等。这是AI的“角色剧本”。
* **`doc/general/general.yaml`**: 定义了所有玩家都需要遵守的通用游戏规则。
* **`doc/general/{role}.yaml`**: 这是一个巧妙的设计。当某个角色（如预言家）存在于本局游戏中时，这个文件里的内容会被**添加**到所有玩家的通用提示中。例如，`doc/general/seer.yaml` 的内容是：“提示: 本局游戏存在【预言家】...”，这会让所有AI都知道预言家的存在并调整自己的策略。
